# 範圍——做了什麼、沒做什麼，以及為什麼

這個 repo 重寫的是我在公司做過的一套 agent 平台的**決策**。那套系統的能力面比這裡寬得多。把差距寫下來，就是這一頁存在的理由。

一個只列出自己做了什麼的 demo，很難被當成工程判斷來讀，因為真正有意思的問題從來不是「你做了什麼」，而是「你決定不做什麼，以及當時說不說得出理由」。以下每一項都是決定，不是遺漏。如果某項缺席是因為它在離線環境下根本做不出有意義的示範，那就照實寫成那個理由，不要包裝成品味。

分組方式是刻意的：有做的全是**控制平面**的性質——誰可以做什麼、資料可以去哪裡、什麼時候停下來；沒做的大多屬於**資料平面**——要檢索什麼、要記住什麼、怎麼替一個答案打分。這條線就是我畫下的 repo 邊界。

## 有做的

每一列是一個機制，不是一個功能；而且每一列都有測試釘住，性質一旦不成立測試就紅。

| 性質 | 機制 | 釘住它的測試 |
|---|---|---|
| 同一個 trigger 永遠走同一條路 | `ROUTE_TABLE` 查表，沒有預設值 | `test_routing.py` |
| 路由決策碰不到任何模型 | 注入式 `Judge`，測試裡全部下毒 | `test_routing.py` |
| 循環贏不過步數上限 | `next_node` 的固定優先序 | `test_routing.py`、`test_handoff.py` |
| 代理只能呼叫自己的工具 | `invoke` 內檢查 `ACCESS` | `test_tool_access.py` |
| 同一張工具表的兩種讀法不會漂移 | `schemas_for` 與 `invoke` 共用 `allowed()` | `test_tool_access.py` |
| 租戶規則只能收窄角色，不能放寬 | `TENANT_DENY` 對 `ACCESS` 做減法 | `test_tool_access.py` |
| 沒有人點頭就不會部署 | `interrupt_before=["approval_gate"]` | `test_hitl.py` |
| 沒有決定不等於同意 | 拒絕寫在 deployer 裡面 | `test_hitl.py` |
| 模型看不到真實識別資訊 | 呼叫前 `privacy.mask` | `test_privacy.py`、`test_audit.py` |
| 還原是一道權限，不是一個步驟 | `privacy.restore` 直接拒絕 | `test_privacy.py` |
| 受限內容不離開部署環境 | `providers.choose` 的地域否決 | `test_providers.py` |
| 容錯可以跨成本層，不能跨地域 | `providers.choose` 的過濾順序 | `test_providers.py` |
| 每一次模型呼叫都走同一道門 | `agents.consult` | `test_audit.py` |
| 每一次呼叫都留紀錄，包含被拒絕的 | `audit.CallRecord` | `test_audit.py`、`test_quota.py` |
| 估算值不會留在帳上 | `BudgetedStream.settle` → `audit.settle` | `test_budget.py`、`test_audit.py` |
| 預算在跨過的那一塊就切斷串流 | `BudgetedStream` 的逐 chunk 計數 | `test_budget.py` |
| 一個租戶花不到另一個租戶的額度 | 以租戶為鍵的 `quota.Ledger` | `test_quota.py` |
| 超額錯誤說得出什麼時候再來 | `QuotaExceeded.retry_after` | `test_quota.py` |
| 閘門逐指標擋，不看混合分數 | `THRESHOLDS` | `test_evals.py` |
| 診斷用的指標永遠不擋 | `UNGATED` | `test_evals.py` |
| 指標缺漏算失敗，不算通過 | `metrics.get(name, 0.0)` | `test_evals.py` |
| 事後調高標準不會改寫舊判決 | `GateResult` 內的策略快照 | `test_evals.py` |
| 「資料不足」是第三種答案，不是「ok」 | `MIN_WINDOW`、零變異守衛 | `test_drift.py` |
| 要求持久化就大聲失敗 | `build_graph(durability="require")` | `test_durability.py` |

其中兩項值得多說，因為它們改變了程式的形狀，而不只是加了東西。

**通往模型只有一道門。** `agents.consult` 是整個套件裡唯一呼叫 `Judge` 的地方，而且有測試盯著這件事。遮罩、供應商選擇、預算、配額、稽核紀錄全部長在這一次呼叫後面，所以新節點是**結構上**拿到這些東西的。另一條路——每個節點自己記得遮罩、自己記得扣配額——是一條每個節點都必須記得遵守的規則，而這種規則遲早會有某個節點沒遵守。原本那套系統的單一出口閘道就是同一個推論的產物；如果只能留一個決策，我留這個。

**還原用的對照表不進 state。** graph state 會被 checkpoint。一份 checkpoint 如果存著 `<EMAIL_1>` 對回真實地址的映射，就等於在**資料真正躺著的地方**把遮罩解開了。所以 `Consultation.mapping` 只在行程內回傳後就丟掉；還原是呼叫端在顯示的當下、對它已授權的檢視者做的事。

## 刻意不做的

### 防護：注入偵測、輸出過濾、提示洩漏檢查

原系統三樣都有，而且支撐它們的數字來自對真實流量量出來的攔截率。

在沒有模型、也沒有攻擊者的離線環境裡，一個過濾器只能用「寫出這些正則時所依據的那些例子」來測。那種測試一定會過，而且什麼都不代表。在這裡放一個，會替 repo 加上看起來最令人安心、實際上最不誠實的一個目錄。

這是整頁裡最清楚的一例：東西沒做，是因為**示範會是假的**，不是因為能力不重要。

### 評測閘門背後的計分器

`run_gate` 吃指標然後判定。它不生產指標。

生產指標——黃金題庫、跑一輪檢索、計算忠實度——是工作量比較大的那一半，而且需要一個活的系統可以打分。沒有活系統時仍然可攜的，是閘門的**策略**：逐指標的閾值、刻意不設閾值的那一個指標、缺漏指標計為零、以及把策略快照進判決裡。那些是被「決定」出來而不是「量」出來的部分，所以留在這裡的是那些。

### 知識生命週期與分層

原系統對知識項有一個六態機，只有正式層可以被檢索，而且這條規則在閘道強制執行，不是在應用層自律。

**強制執行的位置**是控制平面決策，而且是個好決策。它守護的那個狀態機不是：那是資料平面的生命週期，在這裡重做等於替一條完全用不到知識庫的部署流程硬發明一個知識庫。可移植的那一半——「守衛要放在繞不過去的地方，不是放在指望每個呼叫端自律的地方」——已經由 `ACCESS` 和地域否決承載了。

### 檢索：混合搜尋、排序融合、重排序

確實有意思，但不是控制平面。一個查詢回來哪些文件，不會改變誰可以部署。

### 微調與少樣本庫

在原系統裡也是非目標，理由到現在仍然成立：在一個答錯代價昂貴的領域，可追溯性比邊際準確度值錢，而調過的權重會讓「它為什麼這樣說」變得更難回答。

### 沙箱隔離

白名單做的是**授權**，不是**圍堵**。一個被允許的工具就在行程內跑，行程碰得到什麼它就碰得到什麼。真正的隔離是容器或獨立行程加上網路政策——那是這個 repo 沒有辦法示範、也不應該假裝涵蓋的維運議題。

### 並行、佇列、帶退避的重試

單一執行、單執行緒。重試與冪等重放是另一個 repo（`idemingest`）的主題，在這裡再做一次只會讓兩邊都變差。

## 有做、但做到哪裡為止

寫在這裡而不是藏在註腳，因為一個藏起自己邊界的示範沒有用。

**遮罩是規則比對，不是 NER。** 地址、內部主機名、帳號代號，靠 pattern。真實部署需要模型型偵測器來抓人名與自由文字裡的識別資訊。偵測器變好時，**機制**不會變——呼叫前遮罩、回應後還原、中間一道權限——變的只有召回率。

**配額帳本是單行程的。** 兩個 worker 各自拿到完整額度，所以真正的天花板是「限額 × worker 數」。共享的強制執行需要共享計數器，共享計數器需要一個儲存。值得展示的是例外的形狀與以租戶為鍵這件事，不是那個儲存。

**供應商健康狀態是輸入，不是量測。** `choose` 接收呼叫端「相信還活著」的那組供應商。正式版會逐供應商追蹤失敗並在冷卻後半開。簡化的是健康狀態從哪裡來，不是排序規則。

**這裡沒有任何東西在串流，所以沒有一道花費檢查落在途中。** `BudgetedStream` 的逐塊守衛是對的，也有測試釘住，但 `consult` 拿到的是 `Judge` 回傳的一整個 `dict`，`_chunks` 只是把它重新切塊——守衛算的是一份已經抵達的回覆。預算與配額都是**呼叫之前**的閘門，結構上對稱，而帳本是 judge 回傳之後才扣，所以額度用盡擋的是下一次呼叫，不是在途的這一次。這是「一次把答案給完」這個 `Judge` 契約的性質，不是這兩個機制的缺口：**真正能省到錢的只有呼叫前那道檢查。**

**複雜度路由拿脈絡長度當代理指標。** 很粗糙，而且就擺在一個常數裡（`HIGH_COMPLEXITY_CHARS`），不是埋起來。

**測試套件不呼叫真實模型。** `examples/gemma_judge.py` 把一個本機模型接到判斷縫上，但測試套件保持離線，這樣「控制平面在所有模型入口都被下毒的情況下照跑」才還是一句可以被斷言的話。

**圖只有中文。** `docs/architecture.md` 是英文頁，內嵌的卻是跟中文頁同樣那四張 SVG。散文與 Mermaid 圖是雙語的，產生出來的 SVG 不是。這是個不一致，不是決定——記在這裡是為了讓它不再是個看不見的不一致。

## 什麼情況下這些答案會改

非目標要附上「什麼條件會讓它重新被打開」，否則那只是偏好。

| 沒做的 | 什麼時候重新評估 |
|---|---|
| 防護過濾器 | 有一個活的端點與真實流量可以量攔截率——**那個數字才是交付物**，不是正則 |
| 計分器 | 有一組黃金題庫，其價值高於手工策展它的成本；實務上意思是有真實查詢可以抽樣 |
| 共享配額 | 超過一個 worker 的那一刻——那是單行程天花板從「近似」變成「錯誤」的第一個時點 |
| 預設持久化 | 任何「暫停會活得比行程久」的部署；掛鉤（`durability="require"`）已經在了，而且已經拒絕假裝 |
| NER 遮罩 | 輸入裡開始出現自由文字型的識別資訊；結構化的那些 pattern 已經夠，其餘的不夠 |
| 沙箱 | 工具開始做讀取以外的事，或工具的參數來自控制平面之外 |

## 出處

這份設計所本的系統是私有的，裡面沒有任何一行程式碼在這裡。移植過來的是推理，寫在 [`design.zh-TW.md`](design.zh-TW.md)。上面有兩個決策——模型呼叫的單一出口，以及「寧可拒絕也不降級」的地域否決——來自一組我描述得出、但沒辦法展示的需求：某個部署環境裡，有些資料完全不被允許離開場域。
